# Faiq Ramzan

**Offensive security leader. Kernel exploit development, C2 development, agentic AI security.**

I direct offensive security teams at [Ebryx](https://www.ebryx.com) in Lahore — Linux kernel research, red team tooling, and agentic AI security. Nine years ago I started out reverse engineering malware, and the throughline hasn't changed: understand a system well enough to break it, then build something that resists breaking.

## What I work on

**Agentic AI & LLM security**
Runtime guardrails for agent infrastructure — tool-use boundaries, agent-to-agent trust, memory isolation, privilege control. Threat modeling and red-team assessment of multi-agent systems.

**Linux kernel research**
Exploit primitive development and CVE adaptation across kernel versions, for a client building a security product.

**Red team tooling**
A custom C2 framework and payload delivery mechanisms, built for our red team's field work.

**Reverse engineering**
Where all of it started, and the reason the rest holds up.

## Why agent security is an exploitation problem

Most people approaching agent security come from an ML background and treat it as a prompting problem. It isn't. Privilege boundaries, trust across untrusted inputs, memory isolation, sandbox escape — these are old exploitation problems wearing a new runtime. I've spent a decade on the old version.
